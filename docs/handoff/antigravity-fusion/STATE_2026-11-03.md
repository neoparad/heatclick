## 5. つなぎ目の問題（融合の最大の障害）

**サイトの呼び名が3つの製品でバラバラで、対応表が無い。**

| 製品 | サイトの呼び名 | 例 |
|---|---|---|
| ugokimap | `tracking_id`（＋内部 UUID） | `CIP_EcwUTHEZdIOAUqum` |
| linkscrawl | ホスト名＋クロール job | `bihadashop.jp` / job_id |
| AIreceipt | collector の site_id | `site_abc` 形式 |

**URL の突き合わせ方も3通りに分かれている。**

- `performance_fusion.py`: 完全一致（`e.url = pp.page_url`）
- `behavior_fusion.py`: 部分一致（`LIKE`、末尾 `/` を除去）
- `content_map.py`: 保存値をそのまま

共通の URL 正規化関数は無い。末尾 `/`・クエリ・大文字小文字の違いで取りこぼす可能性がある（**実データでの取りこぼし率は未確認**）。

## 6. 既知の品質リスク（画面に出す前に知っておくこと）

- **ugokimap の `is_agent` 判定**: `is_agent=1` の 99.9% が `no_plugins` という単一の弱いシグナル（Safari・モバイル Chrome でも発生）に依存。人を AI と誤判定している疑い。**未検証。** AI と人を並べて見せる製品なので、この較正は融合の前提条件。
- **aiseo/web の「空UA」63件**: こちらは別問題。探索パス・404率79%・短時間集中の3つが一致し、脆弱性スキャンと結論済み。`no_plugins` 問題と混同しないこと。
- **AIの「なりすまし確定」表示**: UA の文字列だけで判定している。IP 照合・署名検証は未実装。`confidence.js` が「単一シグナルのみ」と表示する仕組みは移植対象。
