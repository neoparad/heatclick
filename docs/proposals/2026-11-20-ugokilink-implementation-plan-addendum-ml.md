## 4. この追加分で特に守ること

実装計画 §2 の一覧に加えて、次を守る。どれも設計書 §8.12 と §8.14 の決まりである。

- **Jev の出力を、学習の正解・重み・先生に使うコードを書かない。** 学習データの組に Jev の出力が 0 件であることを、出どころの検査で機械的に確かめる。Jev の出力で「人に回す件を選ぶ」処理も、法務の確認が記録されるまで閉じておく（選ぶのは生成モデルの確率と無作為の抜き取りで行う）。
- **Jev に送るのは公開ページの文だけ。** 訪問者のデータ、検索クエリ、集計値は送らない。実際の呼び出しは、契約（保存の期間と削除の条件）と地域のゲートが通るまで閉じたままにし、代役の応答で試験する。
- **生成モデルに渡すのは、公開ページの文と、集計・群の特徴まで。** 訪問者 1 人ずつの行は渡さない。
- **基盤モデルと追加部品はサーバーでだけ動かす。** ブラウザとエッジへ配るのは、単独で動く軽い分類器だけ（50 KB・整数演算・署名）。
- **生成モデルに、成約や効果を直接当てさせない。** 出力の根拠の強さは `inferred` まで。説明の中の数字は、計算の結果への参照に限る。
- **ラベルは 3 つに分ける**（学習用、選定と調整用、最終の評価用）。同じページの系譜やほぼ同じ文が、束をまたいで入らないようにする。
- **モデルの重みと学習データをリポジトリにコミットしない。** 成果物は内容ハッシュで保存先に置き、登録簿から引く。

## 5. 今は開けられないゲート（作り終えて、閉じたまま進む）

- 人のラベル（300 件以上、仕事ごと）: 集める口と採点の要領までを作る。ラベルを付けるのは人。
- 追加部品の昇格: 学習・評価・昇格の判定まで実装し、作り物のデータで経路を試験する。本物の判定はラベルがたまってから。
- 仮説用の部品: 実験の結果が届くたびに挑戦者を更新する仕組みまで作る。昇格は、独立した実験の数がそろうまで閉じる。
- 基盤モデルの選定: 比べる仕組みを作る。選ぶのは評価の結果とライセンスの確認の後。
- GPU の計算基盤: 学習と推論のジョブの定義までを作る。契約と実行はオーナー作業。
