Web行動分析ツール比較レポート

GA4 / BigQuery Export / Microsoft Clarity / UGOKI MAP

2026年3月 作成

G

GA4

全体傾向の把握に強い無料ツール。Google広告と直結。詳細分析には制限多い。

BQ

BigQuery Export

GA4の生データをSQL分析。サンプリング解除。ただしGA4の収集制限は残る。

C

MS Clarity

無料のUX分析特化ツール。セッション録画とヒートマップが強い。データ分析機能は限定的。

U

UGOKI MAP

収集レイヤーから独自設計。全ツールで取得不可能な粒度のデータを制限なしで保持。

CV経路分析 — 「流入メディア × ユーザー回遊経路」を可視化できるか？

CVに至るまでのユーザー回遊経路を視覚的に分析する機能。GA4の探索レポートでは経路図を作成できるが、流入メディア（organic / cpc / referral等）をステップに含めることができない。BigQueryならデータとしては取得可能だが、ビジュアライゼーションに大きな制約がある。

BigQuery + Pythonで「流入メディア付き経路図」を作る場合の現実

技術的にできること
1

# BigQuery SQL例
SELECT
  traffic_source.medium,
  page_location,
  event_timestamp
FROM `project.analytics.events_*`
WHERE user_pseudo_id IN (
  -- CVしたユーザー
  SELECT user_pseudo_id
  FROM ... WHERE event_name = 'purchase'
)

GA4 の設定手順

1
GA4管理画面で有効化
プロパティ設定 → レポート用識別子 → 「User-IDとデバイスのデータに基づく」を選択
これをやらないとUser-IDが機能しない
2
GTMで変数を作成（GTM利用時）
GTM → 変数 → 新規 → データレイヤー変数「userId」を作成
3
サイト側JSでdataLayerに送信
// ログイン成功時に実行
dataLayer.push({
  userId: 'member_5821'
});
4
GTMのGA4タグにUser-IDを紐付け
GA4設定タグ → 「User-IDを設定」フィールドに変数を割り当て → GTMを公開
gtag.js直書きの場合（GTM不使用時）
gtag('config', 'G-XXXXXXX', {
  'user_id': 'member_5821'
});
できること
✓ログイン後のuser_id付きデータをAWS会員DBと結合可能（BQ経由）
✓会員別のCV時流入元・ページ遷移・プラン別比較
制限
✗設定前の過去データには遡及適用されない
✗ログイン前の匿名行動はCookie(client_id)切れリスクで紐付け不確実
✗User-IDレポートは「探索」から手動で作成が必要
✗標準レポートにUser-ID軸はデフォルト非表示
✗経路分析は10ステップ制限が残る

UGOKI MAP の設定手順

1
ログイン成功時にJSを1行追加
// これだけ。管理画面の設定変更なし
ClickInsight.track({
  event_type: 'identify',
  user_external_id: 'member_5821'
});
これで完了。他に必要な設定はありません。
できること
✓管理画面の設定変更不要
✓GTM不要
✓ログイン前の匿名行動も自動紐付け
（localStorage の user_id が同一のため）
✓全レポートで即座に会員IDで分析可能
✓ステップ数制限なし — 全ページ遷移を追跡
✓AWS等の外部DBとexternal_idで即時結合
紐付けの仕組み
初回訪問 → user_id: abc123（自動生成・匿名）
2回目訪問 → user_id: abc123（同一localStorage）
会員登録 → user_id: abc123 = external_id: member_5821
→ 初回訪問〜会員登録までの全行動が member_5821 に紐付く
GA4 + BigQuery の場合、同じシナリオで起こること
初回訪問 → client_id: xyz789（匿名Cookie）
2回目訪問 → client_id: xyz789（同一Cookieなら同一）
会員登録 → user_id: member_5821 を送信
→ ログイン後のデータはuser_idでAWS会員DBと結合可能（BQ保存済みなら永久）
→ ログイン前の匿名行動はBQでclient_id結合を試みることが可能
→ ただし初回訪問〜ログインまでにCookieが切れていた場合のみ紐付け不可
