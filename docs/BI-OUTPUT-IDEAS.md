# HeatClick BIツール アウトプット案

ClickHouseに蓄積されたデータから、ヒートマップ以外にBIツールへ出力可能な情報の整理。

---

## 1. ユーザー行動分析

| 指標 | データソース | 活用例 |
|------|-------------|--------|
| **ページ別クリック率（CTR）** | `events` (click_x/y, element_*) | どのページのどの要素が最もクリックされるか |
| **デッドクリック・レイジクリック率** | `events` (event_type: dead_click/rage_click) | UX問題箇所の特定。レイジクリック多い=ユーザー不満 |
| **スクロール到達率** | `heatmap_events` (scroll) | ページのどこまで読まれているか。CTAの最適配置に活用 |
| **読了エリア・滞在時間** | `heatmap_events` (read) | どのセクションに何秒注目しているか |
| **離脱ポイント分析** | `sessions` (exit_page) + scroll_percentage | ページのどこで離脱しているかを可視化 |

## 2. コンバージョン・収益分析

| 指標 | データソース | 活用例 |
|------|-------------|--------|
| **コンバージョンファネル** | `sessions` (conversion_type/value) + `events` | 流入→クリック→CVの各ステップ転換率 |
| **CV寄与要素ランキング** | `events` (element_text/href) × conversion | CVしたセッションで最もクリックされた要素TOP10 |
| **ページ別売上貢献** | `sessions` (total_revenue) × landing_page | どのLPが最も売上に貢献しているか |
| **クリック→CV率（要素別）** | `events` filtered by conversion sessions | ボタンAとボタンB、どちらがCVに繋がるか |

## 3. 流入元・広告効果分析

| 指標 | データソース | 活用例 |
|------|-------------|--------|
| **UTM別セッション・CV** | `sessions` (utm_source/medium/campaign) | どの広告キャンペーンが最も効果的か |
| **gclid/fbclid別行動比較** | `events` (gclid/fbclid) | Google広告とFacebook広告ユーザーの行動差 |
| **リファラー別エンゲージメント** | `events` (referrer) × scroll/read | 流入元ごとのスクロール深度・滞在時間の違い |
| **GSCクエリ×行動紐付け** | `gsc_data` + `events` | 「このキーワードで来た人はここをクリックする」 |

## 4. デバイス・UX分析

| 指標 | データソース | 活用例 |
|------|-------------|--------|
| **デバイス別CV率** | `sessions` (device_type) × conversion | モバイルとPCのCV率ギャップ |
| **デバイス別クリック位置分布** | `events` (click_x/y × device_type) | モバイルで押しにくいボタンの発見 |
| **ビューポート別スクロール率** | `events` (viewport_width/height × scroll_%) | 画面サイズごとの閲覧行動の違い |

## 5. 時系列トレンド

| 指標 | データソース | 活用例 |
|------|-------------|--------|
| **日別/週別/月別PV・セッション推移** | `sessions` (start_time) | トラフィックトレンド |
| **時間帯別アクティビティ** | `events` (timestamp) | ピークタイム特定→広告配信最適化 |
| **WoW/MoM比較** | `statistics` API既存 | 前週比・前月比の自動算出 |
| **ページ改修前後の比較** | 任意期間の行動データ差分 | A/Bテスト的な効果検証 |

## 6. サイト横断・ポートフォリオ分析

| 指標 | データソース | 活用例 |
|------|-------------|--------|
| **サイト別パフォーマンス比較** | `sites` × `sessions` | 複数サイト運用時のベンチマーク |
| **サイト別CVR・ARPU** | `sessions` (total_revenue ÷ unique users) | どのサイトが最も収益効率が良いか |

---

## 特に価値が高いもの（TOP 5）

1. **GSCクエリ × クリック行動の紐付け** — 「検索意図→実際の行動」が見える。他ツールにない独自価値
2. **レイジクリック/デッドクリック集計** — UX改善の優先度がデータで決まる
3. **コンバージョン寄与要素ランキング** — CVしたセッションの行動パターンをリバースエンジニアリング
4. **スクロール到達率 × CTA配置分析** — CTAがスクロール到達率50%の位置にあるなら半分のユーザーに見られていない
5. **UTM/広告ID別の行動品質スコア** — 単なるCV数ではなく、エンゲージメント品質で広告を評価

## BIツール連携方法

ClickHouseは直接BIツール連携が可能：

- **Grafana** — ClickHouseプラグインあり（無料）
- **Metabase** — ClickHouseドライバー対応
- **Looker Studio** — ClickHouse connectorまたはAPI経由
- **Tableau** — JDBC/ODBCドライバー

既存APIエンドポイント（`/api/statistics`, `/api/clicks`, `/api/heatmap`）をJSON出力してBIツールに食わせる方法も可能。

## API化について

現在の内部APIエンドポイントを外部公開用に拡張することで、クライアントが自社BIツールから直接データ取得できるようになる。検討事項：

- 認証（APIキー / OAuth）
- レート制限
- レスポンスフォーマット（JSON / CSV）
- ページネーション
- Webhook（リアルタイム通知）

## 市場の現状：競合との差別化

### 主要ヒートマップツールのデータ提供状況

| ツール | ヒートマップ | 生データAPI | DB直接接続 | データエクスポート |
|--------|:-----------:|:----------:|:----------:|:----------------:|
| Hotjar | ○ | × | × | CSVのみ（限定的） |
| Microsoft Clarity | ○ | × | × | × |
| Mouseflow | ○ | △（一部） | × | CSV |
| Lucky Orange | ○ | × | × | × |
| Crazy Egg | ○ | × | × | レポートPDFのみ |
| Contentsquare | ○ | △（Enterprise） | × | △ |

ほとんどが**ダッシュボードの中で完結**させる設計。ユーザーに生データを触らせない。

### なぜ他社がやらないか

- **ロックイン戦略** — データを囲い込むことで解約を防ぐ
- **インフラコスト** — クリック単位の生データは膨大。API公開するとクエリ負荷が跳ね上がる
- **ビジネスモデル** — 「見せる」ことが価値。データそのものを渡すと自社ツールの存在意義が薄れる

### HeatClickの独自ポジション

「ヒートマップツール」ではなく **「ユーザー行動データプラットフォーム」** として打ち出せば、競合と完全に別カテゴリーになる。Hotjarの競合ではなく、GA4やSegmentの行動データ版という立ち位置。

- **行動データウェアハウス** — ヒートマップはあくまで可視化の一つ。本質的な価値はClickHouseに溜まっている生データそのもの
- **BIツール直接接続** — Grafana/Metabase/Looker Studioから直接クエリできる
- **GSC × 行動データの紐付け** — 「検索クエリ→ページ内行動」を生データレベルで持っているツールは他にない
- **自社データとして所有できる** — 外部ツール依存なし、自社ClickHouseにデータがある安心感

## ビジネスモデル：BIツール付きSaaS

データ収集 + 分析 + 可視化を全部自社で持てる構造が最大の強み。

```
通常の会社:  Hotjar(収集) → エクスポート → Looker(可視化) → 分析
HeatClick:   タグ設置(収集) → ClickHouse(蓄積) → 自社BI(可視化・分析)
```

中間コストゼロ、データの抜け漏れゼロ、カスタマイズ自由。

### 売り方のパターン

**パターンA: BIツール込みのSaaS**
- HeatClickのタグを入れるだけで、行動データBIダッシュボードが使える
- Hotjar + Looker Studioを1つにしたもの、という見せ方
- 月額課金

**パターンB: 業界特化BI**
- EC向け：「どの商品画像がクリックされてCVに繋がったか」
- LP制作会社向け：「CTA配置の最適化レポート自動生成」
- 広告代理店向け：「UTM別の行動品質スコアダッシュボード」
- 業界ごとにテンプレBIを用意して売る

**パターンC: レポート納品型**
- クライアントのサイトにタグ設置→月次で分析レポート自動生成
- コンサル的な売り方。ツール代+分析フィーで単価が上がる

### 競合が真似するコスト

他社がこれを再現しようとすると：

1. ヒートマップツール契約（Hotjar: 月$80〜）
2. データエクスポート（手動 or API制限あり）
3. BIツール契約（Looker: 月$300〜）
4. データパイプライン構築
5. ダッシュボード構築

**5ステップかかるものを、1つのプロダクトで提供できる。**

特にパターンBの業界特化は刺さりやすい。「EC向けクリック行動分析BI」のように絞ると、営業しやすく単価も上げやすい。

## HeatClick × PageSpeed Insights 連携：データドリブンLPO

### 概要

自社の既存ツール `my-gsc-analyzer-ai` にはPageSpeed Insights分析モジュールが実装済み。
HeatClickの行動データと組み合わせることで、LPOコンサルティングの精度が飛躍的に向上する。

```
HeatClick:          ユーザーが「何をしているか」（行動データ）
PageSpeed Insights:  ページが「どう表示されているか」（技術データ）
─────────────────────────────────────────────────────────
連携:               「なぜユーザーがそう行動するか」の因果関係が分かる
```

### my-gsc-analyzer-ai の PageSpeed 機能（実装済み）

- **競合比較分析**: 自社 + 競合3社のLighthouseスコア一括取得（Performance / Accessibility / Best Practices / SEO）
- **Core Web Vitals計測**: LCP / FID(INP) / CLS / FCP / TTI
- **Deep Analysis（Puppeteer）**: CSS/JSカバレッジ、DOM構造、画像最適化、リソース分析
- **AI改善提案（Gemini）**: PageSpeed + Deep Analysis結果をGeminiで分析、優先度付き改善プラン生成
- **3フェーズUI**: 競合比較 → 深堀り分析 → 詳細改善プラン（コード例付き）

### 連携シナリオ

#### 1. LCP × スクロール離脱の因果分析
- PageSpeed: LCPが4秒（遅い）
- HeatClick: ファーストビューでのスクロール到達率が30%
- **結論**: 表示が遅いから離脱している。デザイン変更ではなく速度改善が先

#### 2. CLS × レイジクリックの紐付け
- PageSpeed: CLSが0.25（レイアウトシフト大）
- HeatClick: 特定エリアでレイジクリック多発
- **結論**: レイアウトがズレてボタンが押せない。CLS改善で解決

#### 3. 未使用CSS/JS × ページ滞在時間
- PageSpeed Deep Analysis: 未使用CSS 60%、未使用JS 45%
- HeatClick: 読了エリア・滞在時間が競合より短い
- **結論**: 重いリソースが体験を悪化させている。削減で改善可能

#### 4. 競合比較 × 行動比較
- PageSpeed: 自社 Performance 65 vs 競合 90
- HeatClick: 自社のCVR低い、スクロール浅い
- **結論**: 技術的な遅さがCVRに直結しているデータ的根拠が出せる

### コンサル付加価値の階層

```
レベル1: HeatClick単体       →「ここがクリックされています」（事実の提示）
レベル2: PageSpeed単体       →「ここが遅いです」（技術の指摘）
レベル3: 両方連携            →「この遅さがCVを○%落としています。改善すると○%上がる見込み」
```

レベル3は因果関係と予測まで出せるため、コンサルの付加価値が大きく異なる。

### 技術的な連携ポイント

- HeatClickのClickHouse（行動データ）と PageSpeed API（技術データ）を同一ページURLで紐付け
- GSCデータ（検索クエリ）も加えると「検索意図 → 表示速度 → ユーザー行動 → CV」のフルファネル分析が可能
- Gemini AI による統合分析で、行動データ+技術データから自動改善提案を生成
