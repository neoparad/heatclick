## 領域別 詳細評価

### 1. データ設計 — 100点（初回: 90点 +10）

**評価ポイント**
- ClickHouseのテーブル設計が優秀。パーティション（月別）、ソートキー（site_id, timestamp）が分析ワークロードに最適化されている
- イベント、セッション、ヒートマップ、画像可視性、動画、フォーム、要素可視性と、UX分析に必要なデータを網羅的に取得できる設計
- CVデータ（`conversion_type`, `conversion_value`, `event_revenue`）がeventsテーブルに組み込まれており、行動×CV分析が1クエリで実行可能
- マルチテナント対応（`site_id`, `org_id`）がスキーマレベルで組み込まれている

**課題（-10点）**
- [x] ~~`heatmap_events`テーブルと`events`テーブルでクリックデータが重複~~ → **解決済み（2026-03-19）**: `heatmap_events`を廃止し`events`テーブルに一本化。`read_y`, `read_duration`カラムを追加
- [x] ~~テーブル間のデータ整合性を保証する仕組みがない~~ → **解決済み（2026-03-19）**: Redisバッファ＋Inngestフラッシュで書き込み失敗時のリトライバッファを実装。2回失敗でログ記録＋破棄（無限ループ防止）

---

### 2. インフラ設計 — 98点（初回: 85点 +13）

**評価ポイント**
- ClickHouse（大量書き込み＋集計）+ Redis（キャッシュ＋リアルタイム）+ Inngest（バッチ処理）の3層構成は、この用途のベストプラクティス
- キャッシュ戦略が明確：ホットデータ→Redis、コールドデータ→ClickHouse
- Vercel（フロント/API）+ Hetzner（DB）の分離も合理的
- Inngestによるcron処理（日次集約、6時間キャッシュウォーミング）が適切に設計されている

**課題（-15点）**
- [x] ~~イベント受信がVercel Serverless経由でタイムアウトのリスク~~ → **改善済み（2026-03-19）**: `maxDuration=60`設定追加、ClickHouse書き込みを`Promise.all()`で並列化。将来的にはCloudflare Workers等の専用エンドポイントも検討
- [x] ~~ClickHouseへの直接書き込みにバッファリング層がない~~ → **解決済み（2026-03-19）**: Redis RPUSH/LPOPによるバッファリング層を導入。APIは即レスポンス返却し、Inngest `flushEventBuffer`（毎分cron）でバッチフラッシュ。Redis障害時はClickHouse直接書き込みにフォールバック
- [x] ~~warmCacheが`desktop` + `click`のみ~~ → **解決済み（2026-03-19）**: デバイス3種（desktop/tablet/mobile）× ヒートマップ3種（click/scroll/read）× 期間3種を網羅するよう拡張

---

### 3. トラッキング設計 — 95点（初回: 85点 +10）

**評価ポイント**
- 1スクリプトでクリック/スクロール/熟読/フォーム/画像可視性/動画を全取得できる統合設計
- バッチ送信（10件 or 5秒間隔）、sendBeacon優先（離脱時のデータロス防止）が正しく実装
- PIIマスク（メール・電話・クレカ自動検出）、IP匿名化によるプライバシー対応
- dead click / rage click検出は競合ツール（Clarity含む）にない差別化要素
- UTM/gclid/fbclid自動キャプチャで広告分析との連携が自然にできる

**課題（-15点）**
- [x] ~~tracking.jsが38KB~~ → **解決済み（2026-03-19）**: コア8.6KB(minified) + 拡張5モジュール(各0.6〜2.6KB)に分割。コアのみで初期ロード完了後、拡張を非同期ロード
- [x] ~~全機能が1ファイルにまとまっており選択不可~~ → **解決済み（2026-03-19）**: `data-extensions="form,image"`属性または`CLICKINSIGHT_EXTENSIONS`グローバル変数で必要な拡張のみ選択可能。`'all'`(デフォルト)/`'none'`/カンマ区切りリスト対応
- [x] ~~Intersection Observerを多用~~ → **解決済み（2026-03-19）**: Intersection Observerは画像・要素可視性の拡張モジュールに分離。不要な場合はロードされないため低スペック端末への影響なし

### 4. API/バックエンド設計 — 93点（初回: 70点 +23）

**評価ポイント**
- APIルートが機能ごとに整理されている
- ClickHouseクエリのパラメータ化（SQLインジェクション対策）が実装済み
- フォールバック設計（集約テーブル→レガシークエリ）が堅実で、段階的な移行を可能にしている
- 外部連携（GSC）が完全実装されている。GA4/BigQuery連携は将来拡張可能

**課題（-30点）**
- [x] ~~認証が未完成~~ → **解決済み（2026-03-19）**: Next.js middleware.tsで全API/ページルートにJWT認証を強制。公開API（/api/track, /api/health等）は除外。AuthGuardコンポーネントもJWT検証＋リダイレクト付きで実装
- [x] ~~Rate Limitingがメモリ内のみ~~ → **解決済み（2026-03-19）**: Redis INCR + PEXPIRE によるRate Limiting実装。Redis障害時はメモリフォールバック
- [x] ~~マルチテナントのデータ分離が不十分~~ → **解決済み（2026-03-19）**: middlewareがJWTからuser_idを抽出しx-user-idヘッダに注入。`verifySiteAccess()`ヘルパーでサイト所有権を検証可能
- [x] ~~エラーハンドリングが不十分~~ → **解決済み（2026-03-19）**: `lib/api-utils.ts`に共通エラーレスポンス関数（`apiError`, `unauthorized`, `forbidden`, `badRequest`, `notFound`）を実装。エラーコード付きの構造化レスポンス
- [ ] API認証トークンのローテーション機構がない（現在は24h固定有効期限のみ）

### 5. UI/フロントエンド設計 — 65点

**評価ポイント**
- shadcn/ui + Tailwind CSSで統一感のあるUI
- ヒートマップ3種（クリック/スクロール/熟読）の切り替えUIが直感的
- Rechartsによるグラフ表示、Lucideアイコンの一貫した使用
- rrweb-playerによるセッションリプレイの再生機能

**課題（-35点）**
- [ ] 画面数が多いが完成度がバラバラ。A/Bテスト、AI診断、レポートなどが骨格のみ
- [ ] AuthGuardが未実装のため、未認証でも全画面にアクセス可能
- [ ] 状態管理（zustand）が導入されているが未使用。コンポーネント間のデータ共有が場当たり的になる可能性
- [ ] ダッシュボードのレスポンシブ対応が不明確
- [ ] ローディング状態やエラー状態のUI表示が不十分

## 競合比較における強み

| 機能 | Clarity | Hotjar | UGOKI MAP |
|---|---|---|---|
| ヒートマップ | あり | あり | あり |
| セッションリプレイ | あり | あり | あり |
| CV定義・追跡 | **不可** | 有料プランのみ | **可能** |
| ファネル分析 | **なし** | 有料プランのみ | **基盤あり** |
| 画像単体の視認性分析 | **不可** | **不可** | **可能** |
| 動画視聴分析 | **不可** | **不可** | **可能** |
| 要素単位の可視性分析 | **不可** | **不可** | **可能** |
| dead click / rage click | rage clickのみ | なし | **両方** |
| フォーム分析 | **なし** | あり | **あり** |
| APIデータ取得 | **ほぼ不可** | 制限あり | **全データ自由** |
| AI診断連携 | **不可** | **不可** | **設計済み（未実装）** |
| 外部ツール連携 | GA4のみ | 一部 | **GSC実装済み（GA4/BigQuery将来対応）** |
| 料金 | 無料 | $32〜/月 | ¥0〜¥24,800/月 |

**UGOKI MAPの最大の強み**: 行動データ（クリック/スクロール/画像視認/動画視聴）とCVデータを突き合わせて「なぜCVしたか・なぜ離脱したか」を要素レベルで推測できること。これはClarityにもHotjarにもできない。
